# 排策智演 —— 车间 AGV 集群路径规划仿真与调度可视化系统

## 一、项目简介

这是一个面向车间作业场景的多 AGV（自动导引车）集群路径规划与调度仿真系统，采用前后端分离与微服务架构。系统在已有后端工程的基础上进行扩展与重构，并独立实现了前端可视化部分。

系统以网格地图对车间进行建模，支持多辆 AGV 的批量加入、运输任务下发、自动路径规划与动态避障，并通过 Three.js 三维场景实时呈现车辆位置、规划轨迹与避让过程。路径规划同时提供 A* 空间占点避让与时间窗冲突避障两种算法，可在系统运行时一键切换、无需重启。

## 二、功能特性

- 网格地图建模：默认 20×20 车间地图，包含障碍物、普通工位与充电点
- 地图可视化编辑：在前端直接添加或删除障碍物并保存
- 多车管理：批量加入 AGV，维护车辆坐标、朝向、状态、电量与任务信息
- 运输任务：选择车辆、起点工位与终点工位下发运输任务，车辆自动执行
- 路径规划：基于 A* 算法自动寻路，支持多种启发式函数
- 动态避障：车辆运行时结合其他车辆位置实时重新规划，避免碰撞
- 双算法可切换：A* 空间避让与时间窗冲突避障在运行时自由切换
- 多车轨迹：同时运行的每辆车各显示一条独立着色的实时轨迹
- 电量与充电：车辆耗电，低电量时自动前往充电点
- 三维可视化：Three.js 渲染地图、工位、障碍物、车辆与路径
- 数据刷新：前端采用定时轮询（1 秒/次）获取实时状态，不依赖 WebSocket

## 四、系统架构与模块

后端为多模块 Maven 工程，共聚合三个模块：

- agv-model：领域模型模块，存放车辆、任务、地图、节点、日志等实体
- agv-service / service-agv：核心业务服务，包含控制器、业务服务、数据映射、路径规划算法与仿真调度器
- gateway：API 网关，负责请求路由与服务转发

核心业务服务内部按职责分包：

- controller：对外 REST 接口，覆盖车辆、任务、地图、日志与算法切换
- service / service.impl：业务逻辑实现
- mapper：数据访问接口与 XML 映射
- astart：传统 A* 求解器、启发式函数、网格地图
- astart.timewindow：时间窗冲突避障算法，包含预约表、时空 A* 与算法模式管理
- utils：仿真器、碰撞避让、寻路、车辆控制与任务调度等运行时组件
- job：定时节拍任务，驱动仿真按拍推进

## 六、核心算法说明

### 1. A* 空间占点避让（spatial）

在传统 A* 寻路基础上，把其他车辆当前占据的网格视为动态障碍。车辆每个仿真节拍都基于当前位置重新规划路径，结合静态障碍物与他车占点选择可通行路线，并由碰撞避让组件处理会车与绕行，保证多车不发生碰撞。

### 2. 时间窗冲突避障（timewindow）

时间窗算法在空间坐标之外引入时间维度，为每个网格顶点和连接边建立带时间的预约记录：

- 预约表（ReservationTable）：以“坐标 + 时间”为键维护顶点预约，以“起点到终点 + 时间”为键维护边预约，防止同点碰撞与对向冲突
- 时空 A*（TimeWindowAStar）：搜索节点同时携带 x、y、t 三个维度，动作包括四个方向移动与原地等待，启发式仍采用空间曼哈顿距离
- 滚动执行：每个节拍结合其他车辆的时空预约重新规划，但只执行下一时刻（t=1）的节点，其余路径下一拍重新计算
- 冲突处理：当暂无可行路径或下一时刻需要让行时，车辆进入等待状态，冲突解除后自动继续

### 3. 运行时切换

算法模式由专门的模式管理器（Spring 单例）持有，内部以原子引用保存当前模式，默认为 spatial，切换时不影响另一套算法的代码。通过以下接口控制：

- `GET /algorithm/mode`：查询当前算法模式
- `POST /algorithm/mode/{mode}`：切换模式，mode 取值为 `spatial` 或 `timewindow`

前端侧栏提供对应切换按钮，点击即切换并同步高亮与说明文字。

## 七、快速开始

### 环境要求

- JDK 17
- Maven 3.9+
- MySQL 8
- Nacos 2.x
- Node.js（含 npm）

### 启动步骤

1. 准备数据库

   创建数据库 `agv_system`，并建立系统所需的车辆、任务、地图、日志、路径等数据表。随后执行本仓库的 `seed_map.sql`，插入一张默认车间地图（含障碍物、工位与充电点），并将其设为当前地图。

2. 启动 Nacos

   启动 Nacos 服务，默认监听 8848 端口，等待其注册中心就绪。

3. 启动后端服务

   先运行业务服务启动类 `MapMainApplication`（默认端口 8000），再运行网关启动类 `GatewayMainApplication`（默认端口 8080）。可在 Nacos 控制台确认两个服务均已注册且健康。

4. 启动前端服务

   进入前端目录安装依赖并启动开发服务器：

   ```bash
   cd agv-map-web
   npm install
   npm run dev
   ```

   浏览器访问 `http://localhost:26880` 即可打开系统界面。

5. 加入车辆并下发任务

   调用批量加车接口（如 `POST /agv/batch/3`）在内存中创建车辆，在前端选择避让算法，再通过任务面板选择车辆与起止工位下发运输任务，即可观察路径规划与车辆运行。

### 注意事项

- 数据库连接地址、账号密码与 Nacos 地址配置在各服务的 `application.yml` 中，请按本机环境调整
- 前端开发环境通过 Vite 代理直连业务服务（8000 端口）；网关对带请求体的 POST 转发存在 502 问题，因此开发阶段由本地代理绕过，网关与 Nacos 仍正常运行
- 后端重启会清空内存中的车辆对象，需要重新批量加车；车辆列表接口读取的数据库记录可能仍显示旧数据，不能据此判断内存中是否有车
- 新增或修改控制器、服务方法后需重启对应 JVM 才能生效，工程未启用热部署
